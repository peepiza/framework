# Сервис планирования репетиций

Приложение для музыкальных групп, позволяющее управлять помещениями и планировать репетиции. 
Проект прошел путь от консольного скрипта до объектно-ориентированного приложения с веб-интерфейсом.

## Используемые технологии
* **Python 3** — основной язык разработки.
* **Django 5.2** — веб-фреймворк для создания серверной части и маршрутизации.
* **HTML / CSS / Bootstrap 5.3** — создание и оформление веб-интерфейса.
* **SQLite и Django ORM** — хранилище данных веб-интерфейса.
* **JSON** — хранилище данных консольного интерфейса.
* **pytest** — автоматизированное тестирование.
* **flake8** — проверка качества и стиля кода (PEP 8).

## Локальный запуск Django

Создайте виртуальное окружение и установите зависимости:

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows PowerShell окружение активируется командой `.\.venv\Scripts\Activate.ps1`.
Для первого запуска скопируйте `.env.example` в `.env` и заполните
`DJANGO_SECRET_KEY` новым локальным ключом. Сгенерировать ключ можно командой
`python -c 'from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())'`.
Сохраните значение в одинарных кавычках. Django получает ключ из окружения,
поэтому перед командами `manage.py` загрузите переменную в текущую оболочку:

```sh
set -a
. ./.env
set +a
python manage.py migrate
python manage.py runserver
```

В PowerShell вместо загрузки `.env` через команду `.` задайте ключ для текущего сеанса
командой `$env:DJANGO_SECRET_KEY = (python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())")`,
затем выполните команды `migrate` и `runserver`.

При первом запуске миграции создают `db.sqlite3` с пустыми таблицами проекта.
Откройте `http://127.0.0.1:8000/`. Помещения, группы и репетиции можно добавить
через админку после создания суперпользователя.

Если есть локальная база ПР7, сначала сделайте резервные копии обеих баз.
После применения миграций выполните
`python manage.py import_pr7_data --source data/rehearsal_planner.sqlite`.
Импорт нужен только для переноса прежних данных. Команда читает источник
в режиме только для чтения и требует пустых целевых таблиц.
Модель репетиции связана с помещением и группой через внешние ключи.
В веб-интерфейсе доступны поиск помещений, проверка доступности на дату,
фильтрация, сортировка и пагинация репетиций, статистика по группам.
Обе базы SQLite и файл `.env` хранятся локально.

Проверки: `python manage.py check`, `python manage.py test` и `pytest`.

### Администрирование и анализ запросов

После миграций создайте учётную запись командой `python manage.py createsuperuser`
и откройте `/admin/`. Для ограниченного доступа назначьте сотруднику разрешения
на просмотр или изменение нужных моделей. Админка поддерживает поиск, фильтры
и массовую отмену или восстановление репетиций.
У репетиций три статуса. Помещение на выбранную дату блокирует только активная запись.
Карточки помещений доступны по slug и по прежнему числовому адресу.

Для локального анализа запросов запустите
`DJANGO_DEBUG_TOOLBAR=1 python manage.py runserver` и откройте панель SQL
на списке, карточке репетиции или следующей странице списка.

### Формы репетиций и фотографии помещений

Фильтры списка передаются через GET и сохраняются при переключении страниц.
После входа через `/admin/` сотрудник с разрешением `add_rehearsal` может
создать репетицию из списка. Разрешение `change_rehearsal` открывает
редактирование и отмену из карточки. При сохранении проверяются дата,
вместимость и занятость помещения и группы. Отменённая запись сохраняется
в истории и освобождает помещение.
С разрешением `change_room` фотографию можно загрузить из карточки
или через админку. Поддерживаются JPEG, PNG и WebP до 5 МБ. Файлы
хранятся локально в `media/`.

## Возможности проекта

### Веб-интерфейс (ПР5)
* Просмотр списка всех помещений.
* Просмотр детальной информации о помещении (вместимость, адрес).
* Проверка доступности помещения на выбранную дату.
* Просмотр списка всех репетиций.
* Просмотр детальной информации о репетиции (группа, помещение, время, статус).
* Кастомная страница ошибки 404.
* Навигация между разделами сайта.

### Консольный интерфейс (сохранен с ПР1–ПР3)
* Добавление групп и участников.
* Добавление и поиск помещений.
* Бронирование и отмена репетиций.
* Сохранение данных в JSON-файлы.

## Основные классы предметной области (`models/`)
* `Room` (помещение) — атрибуты: `id`, `name`, `capacity`, `address`; методы: `is_suitable_for()`, `__str__`.
* `Band` (группа) — атрибуты: `id`, `name`, `genre`, `members_count`.
* `Member` (участник) — атрибуты: `id`, `name`, `instrument`, `band_id`.
* `Rehearsal` (репетиция) — атрибуты: `id`, `band`, `room`, `rehearsal_date`, `start_time`, `is_cancelled`; метод: `cancel()`.
